## 1. TypeScript 실습 환경 준비하기

먼저 0주차에서 설치한 Node.js와 pnpm을 확인해요.

```bash
node -v
pnpm -v
```

- TypeScript 프로젝트 폴더 준비하기
    
    터미널에서 아래 명령을 차례로 실행해요.
    
    ```bash
    mkdir week1-typescript
    cd week1-typescript
    pnpm init
    pnpm add -D typescript
    mkdir src
    ```
    
    `pnpm add -D typescript`는 이 프로젝트에서 사용할 TypeScript 컴파일러를 개발 도구로 설치해요. 설치가 끝나면 `package.json`과 `node_modules`가 생겨요.
    
- TypeScript 검사 규칙 작성하기
    
    프로젝트의 가장 바깥 폴더에 `tsconfig.json` 파일을 만들고 아래 내용을 작성해요.
    
    ```json
    {
      "compilerOptions": {
        "target": "ES2022",
        "rootDir": "./src",
        "outDir": "./dist",
        "strict": true
      },
      "include": ["src/**/*.ts"]
    }
    ```
    
    - `rootDir`: TypeScript 파일을 작성할 폴더를 정해요.
    - `outDir`: 컴파일된 JavaScript 파일이 만들어질 폴더를 정해요.
    - `strict`: 타입을 더 꼼꼼하게 검사해요.
- 첫 TypeScript 파일 컴파일하고 실행하기
    
    `src/index.ts` 파일을 만들고 아래 코드를 작성해요.
    
    ```tsx
    const courseName = "TypeScript";
    console.log("이번 주 학습 주제: " + courseName);
    ```
    
    터미널에서 TypeScript 파일을 컴파일해요.
    
    ```bash
    pnpm exec tsc
    ```
    
    `dist/index.js` 파일이 생기면 Node.js로 실행해요.
    
    ```bash
    node dist/index.js
    ```
    
    터미널에 `이번 주 학습 주제: TypeScript`가 출력되면 준비가 끝났어요. `courseName`의 값을 바꾸고 다시 컴파일한 뒤 결과도 확인해 보세요.
    
- 추가로 알아보기: 컴파일과 타입 검사
    
    `pnpm exec tsc`는 타입을 검사하고 JavaScript 파일을 만들어요. JavaScript 파일을 만들지 않고 타입 오류만 확인하고 싶다면 `pnpm exec tsc --noEmit`을 사용해요.
    
    TypeScript의 타입 표시는 검사할 때 사용되고, 컴파일된 JavaScript 파일에서는 사라져요.
    
- 같이 보면 좋은 자료
    
    [TypeScript 설치 안내](https://www.typescriptlang.org/download/)에서 프로젝트에 TypeScript를 설치하는 방법을 확인할 수 있어요.
    

## 2. TypeScript가 필요한 이유와 동작 과정

TypeScript는 JavaScript 코드가 실행되기 전에 값의 종류가 알맞은지 확인해요. 이 과정을 이해하려면 컴파일 타임과 런타임을 구분해야 해요. 먼저 JavaScript에서 놓치기 쉬운 실수를 살펴보고, 같은 코드를 TypeScript가 언제 막아 주는지 확인해요.

- JavaScript에 타입 기능을 더한 언어
    
    TypeScript는 JavaScript 문법에 타입을 표현하는 기능을 더한 언어예요. 이런 관계를 **상위 집합(superset)**이라고 해요.
    
    JavaScript에서 배운 문법을 바탕으로 필요한 곳부터 타입을 추가할 수 있어요. 기존 코드를 한 번에 모두 바꾸지 않고 작은 파일이나 함수부터 TypeScript로 옮기는 것을 **점진적으로 적용한다**고 해요.
    
    타입을 추가하면 편집기에서 잘못된 프로퍼티나 함수 사용을 더 일찍 알려 주고, 변수와 함수가 어떤 값을 다루는지도 쉽게 확인할 수 있어요.
    

```jsx
function addScore(currentScore, bonusScore) {
  return currentScore + bonusScore;
}

console.log(addScore(80, "10")); // "8010"
```

숫자 `80`과 문자열 `"10"`을 더했기 때문에 `90`이 아니라 `"8010"`이 나와요. TypeScript에서는 매개변수에 숫자 타입을 붙여 이런 실수를 실행 전에 찾을 수 있어요.

```tsx
function addScore(currentScore: number, bonusScore: number) {
  return currentScore + bonusScore;
}

console.log(addScore(80, 10)); // 90
```

반환 타입은 `return`에 적힌 값을 보고 `number`로 추론하므로 따로 적지 않았어요.

- 컴파일은 무엇을 할까요?
    
    컴파일은 TypeScript 코드를 실행 가능한 JavaScript 코드로 바꾸는 과정이에요. `tsc`는 이 과정에서 먼저 타입을 검사하고, 타입 표시를 지운 뒤 JavaScript 파일을 만들어요.
    
    `src/index.ts`에 아래 코드를 작성해요.
    
    ```tsx
    const currentLevel: number = 1;
    console.log("현재 레벨: " + currentLevel);
    ```
    
    터미널에서 컴파일해요.
    
    ```bash
    pnpm exec tsc
    ```
    
    `dist/index.js`의 핵심 부분은 아래처럼 타입 표시가 사라진 JavaScript 코드예요.
    
    ```jsx
    const currentLevel = 1;
    console.log("현재 레벨: " + currentLevel);
    ```
    
    `number` 같은 타입 정보는 컴파일할 때만 사용하고 런타임에는 남지 않아요.
    
- 컴파일 타임과 런타임
    
    
    | 구분 | 언제인가요? | 무엇을 확인하나요? |
    | --- | --- | --- |
    | 컴파일 타임 | `pnpm exec tsc`를 실행할 때예요. | 타입 오류를 검사하고 JavaScript 파일을 만들어요. |
    | 런타임 | `node dist/index.js`로 JavaScript를 실행할 때예요. | 실제 값을 계산하고 Console에 결과를 출력해요. |
    
    컴파일 오류는 코드가 실행되기 전에 발견돼요. 런타임 오류는 컴파일을 통과한 JavaScript를 실제로 실행하는 동안 발생해요.
    
- 컴파일을 통과해도 런타임 오류가 날 수 있어요
    
    `src/index.ts`에 아래 코드를 작성해요.
    
    ```tsx
    const memberNames = ["광수"];
    console.log(memberNames[5].toUpperCase());
    ```
    
    `pnpm exec tsc`는 오류 없이 끝날 수 있어요. 하지만 `node dist/index.js`로 실행하면 존재하지 않는 여섯 번째 값을 사용했기 때문에 아래 런타임 오류가 발생해요.
    
    ```
    TypeError: Cannot read properties of undefined (reading 'toUpperCase')
    ```
    
    <aside>
    💡
    
    TypeScript는 많은 실수를 미리 찾지만 실제 데이터의 모든 상태까지 보장하지는 않아요. 컴파일 성공과 실행 성공을 모두 확인해야 해요.
    
    </aside>
    
- TypeScript가 컴파일 타임에 알려 주는 실수
    - 함수가 원하는 값과 다른 종류의 값을 전달했어요.
    - 객체에 필요한 프로퍼티가 빠졌어요.
    - 없을 수도 있는 값을 바로 사용했어요.
    - 글자를 위한 기능을 숫자에 사용했어요.
    
    타입 오류는 코드를 실행하기 전에 실수를 알려 주는 안내문이에요.
    
- 미니 실습: 컴파일 오류와 런타임 오류 구분하기
    
    `src/index.ts`에 아래 코드를 입력해요.
    
    ```tsx
    function introduceStudent(studentName: string, currentLevel: number) {
      return studentName + " 님은 현재 " + currentLevel + "레벨이에요.";
    }
    
    introduceStudent("광수", "1");
    ```
    
    1. `pnpm exec tsc --noEmit`을 실행하고 오류가 컴파일 타임과 런타임 중 언제 발생했는지 적어요.
    2. 오류 메시지에서 기대한 타입과 전달한 타입을 찾아요.
    3. `"1"`을 `1`로 바꾸고 타입 오류가 사라지는지 확인해요.
    4. 앞의 배열 예제와 어떤 점이 다른지 한 문장으로 비교해요.

## 3. 원시 타입, 객체 타입과 타입 추론

JavaScript가 실행될 때 값은 크게 원시 값과 객체 값으로 나눌 수 있어요. TypeScript는 각 값의 종류를 타입으로 표현하고, 처음 넣은 값을 보고 타입을 추론할 수 있어요. 이번 단원에서는 자주 사용하는 원시 타입부터 확인한 뒤 객체 값과의 차이를 살펴봐요.

`src/index.ts`에 아래 코드를 작성하고 마우스를 변수 이름 위에 올려 추론된 타입을 확인해 보세요.

```tsx
let studentName = "광수";
let currentLevel = 1;
let isCompleted = false;

console.log(studentName, currentLevel, isCompleted);
```

- `string`: 글자를 나타내요.
- `number`: 정수와 소수를 포함한 숫자를 나타내요.
- `boolean`: `true` 또는 `false`를 나타내요.
- 원시 값과 객체 값
    
    객체 값은 여러 값을 프로퍼티로 묶을 수 있고 내부 내용을 바꿀 수 있어요.
    
    | 구분 | 이번 주차의 예시 | 비교하는 방법 |
    | --- | --- | --- |
    | 원시 값 | 문자열, 숫자, 불리언, `null`, `undefined` | 값이 같으면 같은 값으로 비교돼요. |
    | 객체 값 | 객체, 배열, 함수 | 내용이 같아도 같은 객체를 가리킬 때만 같다고 비교돼요. |
    
    `src/index.ts`에 아래 코드를 작성하고 실행해요.
    
    ```tsx
    const firstMember = { name: "광수" };
    const secondMember = { name: "광수" };
    const sameMember = firstMember;
    
    console.log(firstMember === secondMember); // false
    console.log(firstMember === sameMember); // true
    ```
    
    `firstMember`와 `secondMember`는 내용은 같지만 따로 만든 객체예요. `sameMember`는 `firstMember`와 같은 객체를 가리키므로 `true`가 나와요.
    
    const로 객체를 선언해도 객체 안의 프로퍼티는 바꿀 수 있어요. const가 막는 것은 변수에 다른 객체를 다시 넣는 일이에요.
    
    앞의 코드를 아래 예제로 바꾸고 실행해요.
    
    ```tsx
    const studyMember = { name: "광수" };
    
    studyMember.name = "지수";
    
    console.log(studyMember.name); // "지수"
    
    // studyMember = { name: "현우" };
    ```
    
    `pnpm exec tsc`와 `node dist/index.js`를 실행하면 `지수`가 출력돼요. 마지막 줄의 주석을 해제하고 `pnpm exec tsc --noEmit`을 실행하면 상수에 다른 객체를 다시 넣을 수 없다는 오류가 보여요. 오류를 확인한 뒤에는 다시 주석으로 바꿔 주세요.
    
- 타입 표기와 타입 추론
    
    콜론 뒤에 타입을 직접 적는 것을 타입 표기라고 해요.
    
    ```tsx
    let assignmentScore: number;
    assignmentScore = 90;
    ```
    
    TypeScript가 값을 보고 타입을 알아내는 것을 타입 추론이라고 해요.
    
    ```tsx
    let courseName = "TypeScript"; // string으로 추론해요.
    let lessonCount = 8; // number로 추론해요.
    ```
    
    값만 보고 타입을 분명하게 알 수 있다면 추론에 맡겨도 좋아요. 처음 값이 없거나 함수의 매개변수처럼 어떤 값이 들어올지 알려 줘야 하는 곳에는 타입을 직접 적어요.
    
- 배열 타입
    
    배열은 여러 값을 순서대로 담는 객체예요. 같은 종류의 값을 모을 때 아래처럼 타입을 작성해요.
    
    ```tsx
    const studentNames: string[] = ["광수", "지수", "현우"];
    const weeklyScores: number[] = [80, 90, 100];
    
    studentNames.push("수빈");
    studentNames.push(123); // number는 넣을 수 없다는 오류가 보여요.
    ```
    
    `string[]`은 문자열만 담는 배열, `number[]`은 숫자만 담는 배열이라는 뜻이에요.
    
- 추가로 알아보기: 다른 원시 타입과 튜플
    
    JavaScript의 원시 값에는 `bigint`와 `symbol`도 있어요. 이번 주차에는 자주 사용하는 `string`, `number`, `boolean`, `null`, `undefined`에 집중해요.
    
    튜플은 들어갈 값의 개수와 순서가 정해진 배열이에요.
    
    ```tsx
    const studentRecord: [string, number] = ["광수", 1];
    ```
    
    첫 번째 값은 문자열, 두 번째 값은 숫자여야 해요.
    
- 미니 실습: 값의 종류와 추론 확인하기
    1. 이름, 현재 주차, 완료 여부를 값만 넣어 변수로 만들어요.
    2. 각 변수에 마우스를 올려 추론된 타입을 기록해요.
    3. 이번 달에 배울 기술을 문자열 배열로 만들어요.
    4. 배열에 숫자를 넣어 보고 컴파일 오류가 생기는 이유를 적어요.
    5. 내용이 같은 객체 두 개를 `===`로 비교하고 결과를 예상한 뒤 실행해요.

## 4. 객체와 함수에 타입 붙이기

객체는 서로 관련된 값을 이름표와 함께 묶어요. 함수는 값을 받아 동작한 뒤 결과를 반환할 수 있어요. 객체의 모양과 함수의 매개변수에는 필요한 타입을 적고, 함수 반환 타입은 TypeScript가 충분히 추론할 수 있는지 먼저 확인해요.

```tsx
const student: {
  name: string;
  level: number;
  isCompleted: boolean;
} = {
  name: "광수",
  level: 1,
  isCompleted: false,
};
```

- 객체의 모양을 타입으로 만들기
    
    같은 모양의 객체를 여러 번 사용한다면 타입에 이름을 붙일 수 있어요.
    
    ```tsx
    type Student = {
      name: string;
      level: number;
      isCompleted: boolean;
      githubId?: string;
    };
    
    const gwangsoo: Student = {
      name: "광수",
      level: 1,
      isCompleted: false,
    };
    ```
    
    `githubId?`처럼 프로퍼티 이름 뒤에 `?`를 붙이면 있어도 되고 없어도 되는 **옵셔널 프로퍼티(optional property)**가 돼요.
    
- 함수의 매개변수와 반환 타입 추론
    
    함수에 들어오는 값은 매개변수, 함수가 반환하는 값은 반환값이라고 해요.
    
    ```tsx
    function createGreeting(studentName: string) {
      return "안녕하세요, " + studentName + " 님!";
    }
    
    const greetingMessage = createGreeting("광수");
    ```
    
    `studentName: string`은 함수에 문자열을 전달해야 한다는 뜻이에요. 반환 타입은 `return`의 문자열을 보고 `string`으로 추론하므로 따로 적지 않았어요.
    
    반환하는 값이 없는 함수의 반환 타입은 `void`로 추론해요.
    
    ```tsx
    function printGreeting(studentName: string) {
      console.log("반가워요, " + studentName + " 님!");
    }
    ```
    
- 화살표 함수의 반환 타입도 추론할 수 있어요
    
    ```tsx
    const calculateTotalScore = (
      assignmentScore: number,
      attendanceScore: number
    ) => {
      return assignmentScore + attendanceScore;
    };
    ```
    
    두 매개변수는 숫자이고 더한 결과도 숫자이므로 반환 타입은 `number`로 추론해요.
    
- 추가로 알아보기: 타입 별칭(type)과 interface의 차이
    
    `type` 키워드로 만드는 **타입 별칭**과 `interface`는 모두 객체의 모양에 이름을 붙일 수 있어요. 차이가 필요한 지점에서 알맞은 도구를 선택하면 돼요.
    
    | 구분 | type | interface |
    | --- | --- | --- |
    | 표현 범위 | 객체뿐 아니라 원시 타입의 별칭과 유니언 타입도 표현할 수 있어요. | 주로 객체의 모양을 표현해요. |
    | 확장 | `&`로 타입을 조합할 수 있어요. | `extends`로 확장할 수 있어요. |
    | 같은 이름을 다시 선언 | 같은 이름으로 다시 선언할 수 없어요. | 서로 호환되는 선언이라면 하나로 합쳐져요. |
    
    type은 &를 사용해 여러 객체 타입을 하나로 조합할 수 있어요. 이를 교차 타입이라고 해요. 조합된 타입에는 양쪽 타입의 프로퍼티가 모두 필요해요.
    
    `src/index.ts`의 기존 코드를 아래 예제로 바꾸고 실행해요.
    
    ```tsx
    type MemberProfile = {
      name: string;
    };
    
    type GithubProfile = {
      githubId: string;
    };
    
    type MemberWithGithub = MemberProfile & GithubProfile;
    
    const gwangsooProfile: MemberWithGithub = {
      name: "광수",
      githubId: "gwangsoo",
    };
    
    console.log(gwangsooProfile.name, gwangsooProfile.githubId);
    ```
    
    pnpm exec tsc와 node dist/index.js를 실행하면 광수 gwangsoo가 출력돼요. name이나 githubId 중 하나를 지우면 필요한 프로퍼티가 빠졌다는 오류가 보여요.
    
    `interface`는 같은 이름으로 다시 선언한 내용을 하나로 합칠 수 있어요. `src/index.ts`의 코드를 아래 예제로 바꾸고 확인해요.
    
    ```tsx
    type StudentName = string;
    
    interface StudyMember {
      name: StudentName;
    }
    
    interface StudyMember {
      level: number;
    }
    
    const member: StudyMember = {
      name: "광수",
      level: 1,
    };
    ```
    
    객체 타입은 두 방법 중 하나를 팀의 규칙에 맞게 일관되게 사용해요. 이번 워크북에서는 문자열 선택지처럼 객체가 아닌 타입에는 `type`을 사용하고, 회원 객체의 모양에는 `interface`를 사용해요.
    
- 미니 실습: 오류를 고쳐 회원 카드 만들기
    
    아래 코드에는 타입 오류가 있어요. 오류 메시지를 읽고 한 번에 하나씩 고쳐 봐요.
    
    ```tsx
    type StudyMember = {
      name: string;
      level: number;
      isLeader: boolean;
    };
    
    const member: StudyMember = {
      name: "광수",
      level: "1",
    };
    
    function createMemberCard(studyMember: StudyMember) {
      return studyMember.name + " 님, " + studyMember.level + "레벨";
    }
    
    console.log(createMemberCard(member));
    ```
    
    1. `level`의 값이 타입과 맞는지 확인해요.
    2. 먼저 `level`을 고치고 다시 타입 검사해요.
    3. 새로 나타난 오류에서 빠진 프로퍼티를 찾아 추가해요.
    4. 함수를 실행하고 반환 타입이 무엇으로 추론되었는지 확인해요.

## 5. 유니언 타입과 타입 좁히기

하나의 값이 여러 타입 중 하나가 될 수 있다면 `|`를 사용해요. 이를 **유니언 타입**이라고 해요.

```tsx
function printMemberId(memberId: string | number) {
  console.log(memberId);
}

printMemberId("member-01");
printMemberId(1);
```

- typeof로 타입 좁히기
    
    `string | number`인 값에는 문자열 기능을 바로 사용할 수 없어요. 먼저 현재 값의 타입을 확인해야 해요.
    
    ```tsx
    function formatMemberId(memberId: string | number) {
      if (typeof memberId === "string") {
        return memberId.toUpperCase();
      }
    
      return "MEMBER-" + memberId;
    }
    ```
    
    `typeof memberId === "string"`인 블록 안에서는 TypeScript가 `memberId`를 문자열로 판단해요. 이렇게 넓은 타입을 더 구체적인 타입으로 줄이는 것을 **타입 좁히기**라고 해요.
    
- 리터럴 타입으로 선택지 정하기
    
    특정 문자열만 사용할 수 있도록 선택지를 정할 수 있어요.
    
    ```tsx
    type MemberRole = "leader" | "member";
    type AttendanceStatus = "present" | "late" | "absent";
    
    const gwangsooRole: MemberRole = "leader";
    const todayStatus: AttendanceStatus = "present";
    ```
    
    `"manager"`처럼 정해 두지 않은 문자열을 넣으면 오류가 보여요. 오타를 막고 가능한 값을 분명하게 알려 줄 수 있어요.
    
- 판별 유니언(Discriminated Union)
    
    객체가 여러 모양 중 하나라면 공통 프로퍼티의 리터럴 값으로 종류를 구분할 수 있어요. 이런 타입을 **판별 유니언**이라고 해요.
    
    ```tsx
    type StudyResult =
      | { status: "success"; completedCount: number }
      | { status: "error"; message: string };
    
    function printStudyResult(result: StudyResult) {
      if (result.status === "success") {
        console.log("완료한 과제: " + result.completedCount);
        return;
      }
    
      console.log("오류: " + result.message);
    }
    ```
    
    `status` 프로퍼티를 확인하면 각 경우에 맞는 프로퍼티만 안전하게 사용할 수 있어요.
    
- 미니 실습: 회원 역할에 따라 문구 바꾸기
    1. `MemberRole`을 `"leader" | "member"`로 만들어요.
    2. 역할을 받아 안내 문구를 반환하는 함수를 만들어요.
    3. 리더라면 `"스터디를 이끌어요."`, 멤버라면 `"스터디에 참여해요."`를 반환해요.
    4. 정하지 않은 역할을 전달하고 오류를 확인해요.

## 6. null과 undefined를 안전하게 다루기

`null`과 `undefined`는 모두 값이 없음을 나타내는 원시 값이에요. 비슷해 보이지만 코드에서 나타내는 의도가 다를 수 있어요. 값이 있는지 확인할 때는 truthy와 falsy의 의미도 함께 알아야 `||`와 `??`를 올바르게 선택할 수 있어요.

`find()`는 배열에서 조건에 맞는 첫 번째 값을 찾는 메서드예요. 조건에 맞는 값이 없으면 `undefined`를 반환해요. 이번 예제에서는 회원을 찾지 못한 경우를 확인하는 데 사용해요.

`src/index.ts`에 아래 코드를 작성해요.

```tsx
type StudyMember = {
  name: string;
  githubId?: string;
};

const members: StudyMember[] = [
  { name: "광수", githubId: "gwangsoo" },
  { name: "지수" },
];

let selectedMember: StudyMember | null = null;
const foundMember = members.find((member) => member.name === "현우");

console.log(selectedMember); // null
console.log(foundMember); // undefined
```

- null과 undefined는 어떻게 다를까요?
    - `null`: 개발자가 지금은 값이 없다고 의도적으로 표시할 때 자주 사용해요.
    - undefined: 값이 아직 정해지지 않았거나, 선택 프로퍼티가 없거나, 검색 결과를 찾지 못했을 때 자주 나타나요.
    
    `strict` 모드에서는 값이 없을 가능성을 타입에 함께 적고, 사용하기 전에 확인해야 해요.
    
    ```tsx
    let selectedMember: StudyMember | null = null;
    const foundMember = members.find((member) => member.name === "현우");
    ```
    
    `selectedMember`는 회원 또는 `null`이고, `foundMember`는 회원 또는 `undefined`예요.
    
- true와 truthy, false와 falsy
    
    `true`와 `false`는 실제 불리언 값이에요. truthy와 falsy는 조건문에서 불리언으로 바뀌었을 때 `true` 또는 `false`처럼 판단되는 값을 뜻해요.
    
    | 구분 | 대표 값 |
    | --- | --- |
    | falsy | `false`, `0`, `-0`, `0n`, 빈 문자열, `null`, `undefined`, `NaN` |
    | truthy | `"광수"`, `1`, 빈 배열, 빈 객체를 포함한 대부분의 값 |
    
    ```tsx
    console.log(Boolean(false)); // false
    console.log(Boolean(0)); // false
    console.log(Boolean("")); // false
    console.log(Boolean("false")); // true
    console.log(Boolean([])); // true
    console.log(Boolean({})); // true
    ```
    
    문자열 `"false"`는 비어 있지 않으므로 truthy예요. 빈 배열과 빈 객체도 객체이므로 truthy예요.
    
- 조건문으로 값이 있는지 확인하기
    
    `foundMember`는 회원 객체이거나 `undefined`예요. 회원 객체는 truthy이고 `undefined`는 falsy이므로 아래 조건문으로 안전하게 좁힐 수 있어요.
    
    ```tsx
    if (foundMember) {
      console.log(foundMember.name);
    } else {
      console.log("회원을 찾지 못했어요.");
    }
    ```
    
    숫자 `0`이나 빈 문자열도 유효한 값이라면 truthy 검사만 사용하지 않도록 주의해 주세요. 이런 값은 `null` 또는 `undefined`와 직접 비교하는 편이 더 정확해요.
    
- 옵셔널 체이닝(optional chaining)으로 프로퍼티 읽기
    
    `?.`는 **옵셔널 체이닝 연산자**예요. 앞의 값이 `null` 또는 `undefined`이면 오류를 내지 않고 `undefined`를 반환해요.
    
    ```tsx
    const githubId = foundMember?.githubId;
    ```
    
    회원이나 GitHub 아이디가 없으면 오류를 내지 않고 `undefined`가 돼요.
    
- 널 병합 연산자(??)와 ||로 기본값 정하기
    
    `??`는 **널 병합 연산자**예요. 왼쪽 값이 `null` 또는 `undefined`일 때만 오른쪽 기본값을 사용해요. `||`는 왼쪽 값이 어떤 falsy 값이든 오른쪽 기본값을 사용해요.
    
    ```tsx
    const studyHour: number | undefined = 0;
    
    console.log(studyHour || 1); // 1
    console.log(studyHour ?? 1); // 0
    
    const nickname: string | null = "";
    
    console.log(nickname || "닉네임 없음"); // "닉네임 없음"
    console.log(nickname ?? "닉네임 없음"); // ""
    ```
    
    `0`과 빈 문자열을 유효한 값으로 유지해야 한다면 `??`가 알맞아요. 모든 falsy 값을 비어 있는 값처럼 처리하려는 의도가 분명할 때만 `||`를 사용해요.
    
    회원 예제에서는 아래처럼 GitHub 아이디가 `null` 또는 `undefined`일 때만 기본 문구를 사용해요.
    
    ```tsx
    const displayGithubId = foundMember?.githubId ?? "등록되지 않음";
    console.log(displayGithubId);
    ```
    
- 추가로 알아보기: non-null 단언 연산자
    
    `foundMember!.name`처럼 `!`를 붙이는 문법을 **non-null 단언 연산자**라고 해요. TypeScript에 값이 반드시 있다고 알릴 수 있어요.
    
    하지만 실제 값이 없다면 런타임 오류가 날 수 있어요. 값이 있다는 근거가 분명하지 않다면 `!`보다 조건문, `?.`, `??`를 먼저 사용해요.
    
- 미니 실습: 값이 없는 경우와 기본값 비교하기
    1. 회원 배열에서 없는 이름을 찾아 `undefined`가 나오는지 확인해요.
    2. `StudyMember | null` 변수에 `null`을 넣고 의도적으로 비어 있는 상태를 표현해요.
    3. 조건문을 사용해 회원이 있을 때만 이름을 출력해요.
    4. 학습 시간이 `0`일 때 `||`와 `??`의 결과를 각각 출력해요.
    5. `?.`와 `??`를 사용해 GitHub 아이디가 없을 때 `"등록되지 않음"`을 출력해요.

## 7. any 대신 unknown 사용하기

`any`는 타입 검사를 거의 끄는 타입이에요. 어떤 값이든 넣고 바로 사용할 수 있지만 잘못된 코드도 놓칠 수 있어요. `unknown`도 어떤 값이든 받을 수 있지만, 사용하기 전에 타입을 확인해야 해서 더 안전해요.

- any와 unknown 비교하기
    
    
    | 타입 | 값 저장 | 바로 사용 | 특징 |
    | --- | --- | --- | --- |
    | `any` | 어떤 값이든 가능 | 가능 | 타입 오류를 놓치기 쉬워요. |
    | `unknown` | 어떤 값이든 가능 | 타입 확인 후 가능 | 사용하기 전에 안전을 확인해요. |
- unknown을 안전하게 사용하기
    
    `unknown`인 값은 `typeof`나 조건문으로 타입을 좁힌 뒤 사용해요.
    
    ```tsx
    function printNickname(nickname: unknown) {
      if (typeof nickname === "string") {
        console.log(nickname.toUpperCase());
        return;
      }
    
      console.log("닉네임은 문자열이어야 해요.");
    }
    
    printNickname("gwangsoo");
    printNickname(123);
    ```
    
    이 함수는 값을 반환하지 않으므로 반환 타입은 `void`로 추론해요.
    

<aside>
🛡️

타입을 모르는 외부 값을 받을 때는 `any`보다 `unknown`을 먼저 생각해요. 확인 없이 사용하는 코드보다 타입을 확인한 뒤 사용하는 코드가 더 안전해요.

</aside>

- 미니 실습: unknown 값 구분하기
    
    `formatStudyWeek` 함수를 만들어요.
    
    - 숫자가 들어오면 `"현재 N주차예요."`를 반환해요.
    - 문자열이 들어오면 `"입력한 주차: 값"`을 반환해요.
    - 그 밖의 값이 들어오면 `"주차를 확인할 수 없어요."`를 반환해요.
    - 반환 타입을 직접 적지 않고 TypeScript가 무엇으로 추론하는지 확인해요.

## 8. 제네릭 <T>로 타입 관계 지키기

제네릭은 함수를 사용할 때 타입을 정할 수 있는 타입의 빈칸이에요. 보통 첫 번째 타입 매개변수 이름으로 `T`를 많이 사용해요. `T`는 특별한 예약어가 아니라 타입을 나타내기 위해 정한 이름이에요.

- 들어온 타입을 그대로 지키는 <T>
    
    `keepValue<T>`는 받은 값을 그대로 반환해요.
    
    ```tsx
    function keepValue<T>(value: T) {
      return value;
    }
    
    const studentName = keepValue<string>("광수");
    const currentLevel = keepValue<number>(1);
    const isCompleted = keepValue(false);
    ```
    
    - `keepValue<string>`의 `T`는 `string`이 돼요.
    - `keepValue<number>`의 `T`는 `number`가 돼요.
    - 타입을 직접 넣지 않은 `keepValue(false)`의 `T`는 값으로부터 `false` 리터럴 타입으로 추론돼요.
    
    반환 타입도 `T`로 추론되므로 따로 적지 않았어요. `any`와 달리 입력한 타입 정보를 잃지 않아요.
    
- 값을 상자 객체에 담기
    
    제네릭은 입력 타입을 객체 안까지 이어 줄 때도 유용해요.
    
    ```tsx
    function createBox<T>(value: T) {
      return { value };
    }
    
    const nameBox = createBox("광수");
    const scoreBox = createBox(100);
    
    console.log(nameBox.value); // "광수"
    console.log(scoreBox.value); // 100
    ```
    
    하나의 함수를 문자열과 숫자에 모두 사용하면서도 각 `value`의 타입을 정확하게 지킬 수 있어요.
    
- 추가로 알아보기: 제네릭 제약 조건
    
    타입 매개변수가 어떤 프로퍼티를 가져야 하는지 최소 조건을 정할 수 있어요. 이를 **제네릭 제약 조건**이라고 해요.
    
    ```tsx
    type NamedMember = {
      name: string;
    };
    
    function getMemberName<T extends NamedMember>(member: T) {
      return member.name;
    }
    ```
    
    `T extends NamedMember`는 `name` 프로퍼티가 있는 타입만 받을 수 있다는 뜻이에요.
    
- 미니 실습: createBox<T> 사용하기
    1. 값을 받아 `{ value }` 객체로 반환하는 `createBox<T>` 함수를 만들어요.
    2. 문자열, 숫자, 회원 객체를 각각 전달해요.
    3. 각 결과의 `value`에 마우스를 올려 추론된 타입을 기록해요.
    4. 함수의 반환 타입을 직접 적지 않아도 입력 타입이 결과에 이어지는지 확인해요.

## 9. strict 모드와 타입 오류 읽기

`strict` 모드는 TypeScript가 코드를 더 꼼꼼하게 검사하도록 만드는 설정이에요. 1단원에서 작성한 `tsconfig.json`에 `"strict": true`를 넣었기 때문에 프로젝트 전체에 엄격한 검사 규칙이 적용돼요.

- JavaScript 파일을 만들지 않고 타입 검사하기
    
    프로젝트 전체의 타입 오류만 확인하려면 아래 명령을 실행해요.
    
    ```bash
    pnpm exec tsc --noEmit
    ```
    
    `--noEmit`은 JavaScript 파일을 새로 만들지 않고 타입 검사만 하겠다는 뜻이에요. 오류가 없다면 별도의 메시지 없이 명령이 끝날 수 있어요.
    
- 오류 메시지를 읽는 순서
    1. 오류가 발생한 파일 이름과 줄 번호를 찾아요.
    2. `Type 'A' is not assignable to type 'B'`에서 실제 타입과 기대한 타입을 구분해요.
    3. 오류가 난 줄의 변수, 함수, 객체 타입을 확인해요.
    4. 코드를 고친 뒤 타입 검사를 다시 실행해요.
    
    <aside>
    💡
    
    오류 문장 전체가 어렵다면 핵심 타입 두 개부터 비교해요. 예를 들어 `string`을 넣었는데 `number`가 필요하다는 부분을 먼저 찾으면 해결 방향이 보여요.
    
    </aside>
    
- 함수 반환 타입을 일부러 명시하는 경우
    
    반환값이 분명한 짧은 함수는 반환 타입을 추론에 맡겨도 좋아요. 함수의 반환 약속을 고정하거나, 빠진 `return`을 컴파일 타임에 찾고 싶을 때는 반환 타입을 직접 적을 수 있어요.
    
    ```tsx
    function createLevelMessage(currentLevel: number): string {
      if (currentLevel > 0) {
        return "현재 " + currentLevel + "레벨이에요.";
      }
    }
    ```
    
    반환 타입을 `string`으로 약속했지만 조건이 거짓일 때 반환하는 문자열이 없어서 오류가 보여요. 반환 타입 명시는 문서를 읽듯 의도를 알려 주고 실수로 반환값이 바뀌는 일도 막을 수 있어요.
    
- 추가로 알아보기: tsconfig.json
    
    `tsconfig.json`은 TypeScript가 어떤 파일을 어떤 규칙으로 검사할지 정해요. 설정을 처음부터 모두 외울 필요는 없어요.
    
    이번 주차에는 다음 두 가지 의미만 알아둬요.
    
    - `strict`: 여러 엄격한 타입 검사 규칙을 함께 켜요.
    - `noEmit`: JavaScript 파일을 만들지 않고 검사만 해요.
    
    `strict` 설정을 임의로 끄기보다 오류의 원인을 이해하고 코드를 고쳐 봐요.
    
- 미니 실습: 오류 두 개 해결하기
    
    아래 코드의 오류를 찾고 `pnpm exec tsc --noEmit`으로 확인해요.
    
    ```tsx
    type WeeklyGoal = {
      title: string;
      targetCount: number;
    };
    
    const weeklyGoal: WeeklyGoal = {
      title: "TypeScript 예제 연습",
      targetCount: "3",
    };
    
    function printGoal(goal: WeeklyGoal): string {
      console.log(goal.title);
    }
    ```
    
    1. 각 오류의 파일과 줄 번호를 확인해요.
    2. 기대한 타입과 실제 타입을 적어요.
    3. `targetCount`의 값을 고치고 다시 검사해요.
    4. `printGoal`이 문자열을 반환하도록 고친 뒤 타입 검사를 다시 실행해요.
    5. 이 예제에서 반환 타입을 명시한 이유를 적어요.

# 🤔 참고 자료

---

학습하다가 모르는 개념이 나오거나 예제가 예상대로 동작하지 않을 때 아래 자료를 참고해 보세요. 처음부터 끝까지 읽을 필요는 없어요. **궁금한 내용을 검색해 사전처럼 찾아보는 것**으로 충분해요.

- [TypeScript 설치 안내](https://www.typescriptlang.org/download/) - 프로젝트에 TypeScript 컴파일러를 설치하는 방법을 확인할 수 있어요.
- [TypeScript for the New Programmer](https://www.typescriptlang.org/docs/handbook/typescript-from-scratch) - 타입 정보가 컴파일 후 사라지는 이유와 런타임 동작을 확인할 수 있어요.
- [TypeScript Handbook: Everyday Types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html) - 원시 타입, 타입 추론, 함수 반환 타입, `null`과 `undefined`를 살펴볼 수 있어요.
- [TypeScript Handbook: Object Types](https://www.typescriptlang.org/docs/handbook/2/objects.html) - 객체 타입과 `interface` 확장, `type` 조합을 더 자세히 확인할 수 있어요.
- [TypeScript Handbook: Generics](https://www.typescriptlang.org/docs/handbook/2/generics.html) - `<T>`가 입력과 결과의 타입 관계를 지키는 원리를 살펴볼 수 있어요.
- [MDN: Nullish coalescing operator](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Nullish_coalescing) - `??`와 `||`가 falsy 값과 nullish 값을 다르게 처리하는 예제를 확인할 수 있어요.
