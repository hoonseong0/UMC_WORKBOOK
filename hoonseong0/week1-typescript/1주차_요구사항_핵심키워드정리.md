# 1주차 요구사항 및 데이터베이스 설계 핵심 키워드 정리

## 1. PK (Primary Key)와 FK (Foreign Key)
- **PK (기본키, Primary Key)**:
  - 테이블 내의 각 행(레코드)을 고유하게 식별할 수 있는 유일한 컬럼입니다. (예: `user_id`, `book_id`)
  - **특징**: 중복된 값을 가질 수 없으며(Unique), 비어있을 수 없습니다(NOT NULL). 주로 확장성을 고려해 `BIGINT` 타입에 자동 증가(Auto Increment) 속성을 주어 사용하거나 UUID를 사용합니다.
- **FK (외래키, Foreign Key)**:
  - 다른 테이블의 PK를 참조하여 테이블 간의 관계를 연결하는 컬럼입니다.
  - **특징**: 자식 데이터가 부모 데이터를 참조할 때, 존재하지 않는 부모 데이터를 참조하지 못하게 강제하여 **참조 무결성**을 보장합니다.

## 2. ERD (Entity Relationship Diagram)
- **정의**: 요구사항 분석을 통해 찾아낸 데이터베이스 내의 개체(Entity, 테이블)들과 그들 간의 관계(Relationship)를 시각화한 다이어그램입니다.
- **역할**: "어떤 데이터를 DB에 저장할까?", "이 데이터와 저 데이터는 어떤 관계일까?"를 고민한 결과물로, 백엔드 개발의 뼈대이자 데이터베이스(DDL) 구축의 청사진입니다.

## 3. 연관관계 및 설정 방법
- **연관관계**: 테이블 간의 논리적 연결 고리로, 주로 **1:1, 1:N (일대다), N:M (다대다)** 관계로 나뉩니다.
- **설정 방법**:
  - **1:N 관계**: 1쪽의 PK를 N쪽의 자식 테이블에서 FK(외래키)로 참조하는 방식으로 설정합니다.
  - **N:M 관계 (다대다 매핑)**: 데이터의 중복 저장을 막기 위해 두 테이블 사이에 **매핑 테이블(중간 테이블)**을 새롭게 생성하여 두 개의 1:N 관계로 풀어냅니다. (예: 사용자와 책 사이의 '대여 내역 테이블'이나 '좋아요 테이블')

## 4. 정규화 (Normalization)
- **정의**: 데이터베이스 설계 시 데이터의 중복을 최소화하고, 수정이나 삭제 시 발생할 수 있는 이상 현상(데이터 꼬임 현상)을 방지하기 위해 테이블을 구조적으로 쪼개고 분리하는 과정입니다.
- **제 1 정규화 예시**: 하나의 컬럼이 여러 값을 가지지 않도록 원자값으로 쪼개거나, N:M 관계를 중간 테이블로 분리하는 과정이 대표적입니다. 

## 5. 반 정규화 (De-normalization)
- **정의**: 데이터 무결성을 희생하더라도 **시스템의 조회 성능(읽기 속도) 향상과 개발 편의**를 위해, 정규화된 테이블을 다시 합치거나 데이터의 중복을 의도적으로 허용하는 과정입니다.
- **예시**: 책의 '좋아요 수'를 구하기 위해 매번 '좋아요' 테이블을 전체 집계(COUNT)하는 것이 성능에 부담이 된다면, 정합성이 조금 떨어질 위험을 감수하더라도 책 테이블 내에 `like_count` 컬럼을 따로 두고 저장하는 방식을 채택할 수 있습니다.

## 6. DB에서의 상속 관계 표현
객체 지향 프로그래밍의 상속 개념을 관계형 DB에서 매핑하는 방법에는 크게 세 가지 전략이 있습니다.
1. **조인 전략 (Join Strategy)**: 부모 테이블과 자식 테이블을 각각 만들고, 자식 테이블의 PK가 곧 부모를 가리키는 FK가 되는 정규화된 방식입니다.
2. **단일 테이블 전략 (Single Table Strategy)**: 상속 관계에 있는 모든 컬럼을 하나의 커다란 테이블에 몰아넣고 `dtype`과 같은 구분자 컬럼을 두어 구분하는 방식입니다. (조인이 필요 없어 빠르지만 NULL이 많아집니다.)
3. **구현 클래스마다 테이블 생성**: 부모 테이블을 두지 않고, 공통 속성을 각 자식 테이블이 모두 독립적으로 가지는 방식입니다.

## 7. 인덱스 (Index)
- **정의**: 데이터베이스 테이블에 대한 **조회(검색) 속도를 비약적으로 높여주는 자료구조**입니다. 책 맨 뒤의 '색인(찾아보기)'과 동일한 역할을 합니다.
- **특징**:
  - 인덱스를 설정한 컬럼은 처음부터 끝까지 다 뒤지는 Full Table Scan을 하지 않고 데이터를 빠르게 찾을 수 있습니다.
  - 단점: 데이터를 추가/수정/삭제할 때마다 인덱스도 함께 업데이트되어야 하므로 **쓰기 성능이 저하**되며, 추가적인 디스크 용량을 차지합니다. 따라서 조회가 잦고 데이터 변경이 적은 컬럼에 전략적으로 사용해야 합니다.
