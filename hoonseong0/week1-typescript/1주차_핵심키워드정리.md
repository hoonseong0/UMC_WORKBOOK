# 1주차 핵심 키워드 정리

## 1. TypeScript와 정적 타입 검사
- **정적 타입 검사**: 코드가 실행되기 전(컴파일 타임)에 변수나 함수의 타입을 확인하여 타입 불일치로 인한 오류를 사전에 방지하는 기능입니다.
- **JavaScript와 TypeScript의 차이**: JavaScript는 런타임에 타입 오류를 발견하지만, TypeScript는 컴파일 타임(코드를 실행하기 전)에 값의 종류가 알맞은지 검사하여 잘못된 프로퍼티나 함수 사용을 더 일찍 알려줍니다.
- **컴파일 타임 vs 런타임**:
  - **컴파일 타임**: `tsc` 명령어를 통해 타입 오류를 검사하고 JavaScript 파일을 만드는 과정입니다. 이때 코드가 실행되기 전에 실수를 발견할 수 있습니다.
  - **런타임**: 컴파일을 통과한 JavaScript 코드를 `node` 등으로 실제로 실행하는 과정입니다. 컴파일 타임에 잡지 못한 오류(예: 존재하지 않는 배열 요소 접근)가 발생할 수 있습니다.
- **타입 정보가 남지 않는 이유**: TypeScript의 주요 역할은 개발 시점과 컴파일 시점의 '안전성 확보'이며, 실제 브라우저나 Node.js 환경에서 코드가 동작하기 위해서는 순수 JavaScript 파일로 변환되어야 하기 때문입니다.

## 2. 타입 추론과 타입 모델링
- **타입 추론 vs 직접 작성**:
  - **타입 추론**: 처음 할당된 값을 보고 TypeScript가 스스로 타입을 유추하는 기능입니다. 값만으로 타입이 명확할 때(예: `let num = 1;`) 유용합니다.
  - **직접 작성(타입 표기)**: 초기값이 없거나, 함수의 매개변수처럼 외부에서 어떤 값이 들어올지 알 수 없을 때 명시적으로 적어주어야 합니다.
- **객체와 함수 형태의 타입 표현**: 객체에 필요한 프로퍼티가 빠졌는지, 함수에 원하는 값과 다른 종류의 값이 전달되었는지 등을 명확하게 정의하여 오류를 사전에 방지합니다.
- **`type` vs `interface`**:
  - **`type` (타입 별칭)**: 객체뿐 아니라 원시 타입, 유니언 타입 등의 별칭 지정이 가능하며, 교차 타입(`&`)으로 결합합니다. 재선언 시 오류가 발생합니다.
  - **`interface`**: 주로 객체의 형태를 정의할 때 사용하며, `extends` 키워드로 확장합니다. 같은 이름으로 재선언 시 자동으로 병합(Merge)되는 특징이 있습니다.

## 3. 유니언 타입과 타입 좁히기
- **유니언 타입 (`|`)**: 하나의 값이 여러 타입 중 하나가 될 수 있음을 표현합니다. 선택 가능한 값의 범위를 제한(예: 리터럴 타입 `"leader" | "member"`)하여 오타나 잘못된 타입 할당을 방지할 수 있습니다.
- **타입 좁히기 (Type Narrowing)**:
  - `string | number`처럼 넓은 범위를 가진 타입을 `if (typeof value === "string")`과 같이 검사하여 더 구체적인 타입으로 좁히는 과정입니다.
  - **판별 유니언(Discriminated Union)**: 공통된 속성(예: `status: "success" | "error"`)의 리터럴 값을 비교하여 객체의 정확한 타입을 안전하게 분기할 수 있습니다.
- **`null`과 `undefined` 처리**:
  - **옵셔널 체이닝 (`?.`)**: 값이 `null` 또는 `undefined`일 경우 런타임 오류 대신 `undefined`를 반환해 안전하게 접근합니다.
  - **널 병합 연산자 (`??`)**: 왼쪽 값이 오직 `null` 또는 `undefined`일 때만 오른쪽 기본값을 사용합니다. (falsy 값인 `0`이나 `""` 등을 유효한 값으로 취급해야 할 때 `||` 대신 사용합니다.)

## 4. 타입 안전성과 제네릭
- **`any` vs `unknown`**:
  - **`any`**: 타입 검사를 무시하고 통과시켜 잘못된 코드도 허용할 위험이 큽니다.
  - **`unknown`**: 어떤 값이든 넣을 수 있지만, 사용 전 반드시 `typeof`나 조건문 등으로 타입을 확인(타입 좁히기)해야 하므로 훨씬 안전합니다.
- **`unknown`과 제네릭(`<T>`)의 활용 상황**:
  - **`unknown`**: 외부에서 어떤 값이 들어올지 알 수 없을 때 안전장치로 사용합니다.
  - **제네릭 (`<T>`)**: 함수나 클래스 호출 시 특정 타입을 유연하게 받으면서도, 그 타입이 반환 타입이나 내부 속성까지 그대로 유지되어야 할 때 사용합니다.
- **제네릭의 타입 관계 유지 원리**: 함수의 타입 부분을 `T`라는 빈칸으로 두고, 함수를 호출할 때 전달된 인자의 타입이 `T`로 추론되면, 결과값 역시 동일한 `T`로 고정되어 입력-출력 간의 타입 일관성을 지킵니다.
